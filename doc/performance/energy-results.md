## Invalidation and display contracts

Historical IOB depends on the rounded calculation timestamp, insulin/TBR/EB history, profile timeline, insulin configuration, therapy preferences and time transforms. Only strictly past values are cached; future values whose calculation later becomes past are never promoted. BS/BCR/TB/EB/CA/TT/PS/EPS and therapy-relevant glucose changes use the existing history path; therapy mutations reset cached insulin values before debounce, including moved timestamps. Profiles, insulin/sensitivity plugin/configuration and typed Aps/Autosens/Absorption/Insulin/Safety/Loop preference changes reset the calculation. DB clear and time/date/time-zone/DST broadcasts reset ADS/cache. Range invalidation includes its boundary; frequent changes conservatively clear more history. Stored objects and returned values are detached copies.

The live overview cache counts consumers of every optional IOB/COB/activity/BGI/deviation/sensitivity flow, including any Wear/widget flow consumer. A consumer/range change requests the current ready generation. Wear BG history is a separate protocol snapshot. Historical navigation retains its own graph chain. Publishing requires both the current generation and the matching range, with range checking under the live cache's range-owner monitor. A new mandatory snapshot can compute while a graph is suspended. Optional work never rewinds the mandatory cycle progress indicator; a worker integration test exercises this path.

500ms is the ordinary event coalescing window, not a claim that overloaded IO can complete a render in500ms. One active plus one pending request bounds notification/Wear backlog. Alarm creation, confirmation/command events, bolus progress and scene actions use their existing immediate paths. Android Auto pop-up content is deduplicated and limited to one new pop-up per10s; the ongoing notification still updates normally. Protocol EventData fields and serial format remain compatible; GraphData is still a full snapshot whenever sent. Runtime mixed-version installation is not claimed.

## Durability, bounds and export

Diagnostics flush every second while the writer is responsive, at buffer pressure, before a critical record, and before export. There is no hard one-second disk deadline during a stalled writer. Saturation/rejection is counted; unflushed RAM may be lost on a crash. An unclean session marks uncertain coverage. Accepted diagnostic WAL batches record original observation count and last aggregated observation timestamp; old WAL rows default to one observation. Aggregation is observation-only and never creates a replacement dosing operation identifier.

Raw Apex/Medtrum traces retain ≤512 entries/512KiB (individual entry≤8KiB) and record truncated/oversized entries. They are persisted only by explicit driver export, with a truncation marker; previously exported rotating files remain available. Ordinary raw payload log dumps are replaced with byte counts. Transport acceptance, operation results, unknown delivery, command/reconciliation evidence and errors remain on the durable paths. Pump model/family and local alias plus a validated UUID are allowed; serials, keys and credentials remain excluded by the telemetry sanitizer. Existing archives keep schema1 with additive policy/aggregation fields.

Store disk usage is maintained incrementally for owned files and reconciled at startup, recovery/error and every15 monotonic minutes. Retention iterates known segment metadata. Admission WAL updates outside the store and other external filesystem changes are picked up by reconciliation; its settled WAL is separately bounded by compaction. Crash/corruption/storage-pressure state is not silently removed.

## Measurements

`metrics/sql-fixture.json` is a synthetic 90-day/10,809-row table fixture with a48h window. Per table, 2,881 point queries become one range query. Point/range+in-memory lookup p95 on this Windows host: TBR3,173/18.1ms, TT2,830/18.8ms, EB2,757/19.6ms, 12 samples each. Both plans use the existing referenceId index and a sort. No patient-DB or battery result is inferred. DynISF was disabled in the user's export, so TDD savings are not presented as its primary current-loop improvement.

The actual-store synthetic100 repeated-state test reports old/new JSONL38,176/491 bytes and old/new store syncs102/3. Counts include store initialization, exclude admission WAL syncs and use no live device. This proves that aggregation/batching works under the stated fixture; the real diagnostic bytes/hour target remains pending. APS_INPUT and safety evidence are intentionally retained even when they dominate total bytes.

Candidate35 KeepAlive maintenance, candidate102 signature download/hash and candidate203 DNS caching were inspected. Their comparable active cost is not established by this export; they are not credited with savings or included in unmeasured broad changes. NS3 lifetime-lock behavior is confirmed in source; the export cannot establish how long that plugin was enabled, so no battery attribution to NS3 is claimed.

## Release and outstanding acceptance

Both apps advance together from code2006 to2007 with their existing package/name/SDK/ABI and public certificate. The workflow retains all original reliability tasks and adds Wear and database tests. Build/test runs have no signing secret; signing uses the existing repository secret on a fresh runner with no Gradle, then independently verifies signatures, manifests, ZIP integrity, full embedded source SHA and file checksums. A key cleanup trap and always-cleanup step cover failures. Changed external Actions are pinned to verified full commits. Google Drive delivery is a separate job; delivery failure cannot disguise whether build/signing succeeded. The existing Watch Face Push packaging and validator token generation remain intact.

The full local 16-module Gradle invocation passed: 3,562 tests, no failures/errors/skips. The final progress fix additionally passed all 28 workflow tests, bringing the unique latest-module total to 3,563. Unchanged tasks may reuse Gradle results; counts, exact log hash and the isolated earlier Garmin socket reset are in `metrics/r1-local-tests.json`. No test was excluded. Baseline: 3,535 tests.

Signed release artifacts must be downloaded from the terminal run for this exact ref/SHA and independently rechecked. Generated `release-run.json` and `release-apks.json` in the local release output folder will record that evidence when available; signed CI artifacts include the APK verification manifest. Unit-test totals and CI status are reported separately from hardware acceptance.

Pending device gates: update old→new Phone/Wear without clearing data; mixed old/new pair in both directions; reconnect/Doze/offline recovery; hidden/open graph and history navigation; both pumps' command confirmation and unknown-delivery recovery without duplicate enactment; paired ordinary-release battery/CPU hours per pump; prepare p95 and diagnostic bytes/hour targets. Existing clinical limits must remain enabled throughout acceptance. Engineering readiness is not a measured battery saving or authorization to change dosing settings.
