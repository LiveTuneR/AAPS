# Проверка на устройствах

Статус: DEVICE_VALIDATION_REQUIRED. Документ описывает будущую проверку, а не результат испытаний.
Применять отдельно к Apex TrueCare 3 и Medtrum Nano. CI, подпись APK и синтетические скриншоты не подтверждают работу на физической помпе.

## Условия

1. Записать SHA APK, сертификат, commit и GitHub run из файлов provenance. Зафиксировать Android, модель телефона, модель/прошивку помпы, источник CGM и интервал показаний.
2. Сохранить действующую конфигурацию приложения и заранее определить возврат к проверенной версии. Не менять профиль/лимиты ради испытания.
3. Сценарии подачи, разрыва связи во время подачи и рестарта выполнять только на отдельном стенде: помпа не соединена с человеком, расходники и испытательная среда соответствуют требованиям изготовителя. Не провоцировать сбои действующей терапии.
4. В обслуживании открыть телеметрию: хранение 7 суток, ошибки/пропуски зафиксировать до начала. Записать время начала и окончания каждого сценария. Не очищать логи между его стадиями.
5. Экспортировать локальный ZIP за период испытания, указав фактический интервал CGM. Root, постоянное подключение ADB и облачная передача для такого экспорта не требуются.
6. Хранить ZIP как медицинские данные. Не прикреплять реальные данные к публичному GitHub issue без отдельной проверки и согласия владельца.

## Как Читать Записи

- `PUMP_QUEUE` с `source=COMMAND_QUEUE`: команда принята очередью; `requestId`, `decisionId`, `generation` связывают события.
- `PUMP_DISPATCH`: очередь передала управление драйверу. Это не подтверждение передачи по радио.
- `PUMP_SENT`: Apex `command_sent` / Medtrum `tx_chunk_accepted`; транспорт принял запрос записи. Это не ACK помпы и не подтверждение дозы.
- `PUMP_RESULT`: callback драйвера/команды; `success`, `enacted`, `queued`, `reportedDeliveredU`. `null` означает неизвестное, не ноль.
- `HISTORY_RECONCILIATION`, `source=PUMP_SYNC`, `stage=DATABASE_SYNC_RETURNED`: завершён вызов синхронизации истории, имеются `pumpId`/`temporaryId`, исходные единицы помпы и записанное значение. Нулевое число изменённых строк может означать повтор уже известной записи, а не ошибку связи.
- `THERAPY_EVENT`: фактические изменения строк БД, включая `rowId`, `version`, `isValid`. Не считать повторные версии отдельными дозами.
- Medtrum не предоставляет подтверждённую общую generation/protocol через диагностический интерфейс: там `null`. Не подставлять вымышленный номер FSM.
- Несопоставленные события сверять по идентификаторам истории и времени, сохраняя неопределённость. Ближайший BG не является доказательством принадлежности дозы.

## Матрица Стенда

Каждую строку выполнить и оформить отдельно для двух помп. Итог каждой строки до получения реального архива: DEVICE_VALIDATION_REQUIRED.

| Сценарий | Действия на стенде | Необходимые свидетельства |
|---|---|---|
| Первое соединение | Выбрать настроенную помпу; запросить чтение статуса | `PUMP_STATE`: переход соединения, initialized, модель/прошивка; запрос и результат чтения |
| Обычный reconnect | Дождаться отключения после опроса; повторить чтение | Новая последовательность соединения; завершение команды; отсутствие повторной терапии |
| BLE-прерывание | Во время только чтения прервать BLE, восстановить, запросить статус | Отключение/ошибка, reconnect, результат следующего чтения; очередь не зависла |
| Перезапуск приложения | Закрыть/открыть приложение без команды подачи | `PROCESS_START`, восстановление запроса расчёта; отсутствие воспроизведения команды помпы |
| Завершение процесса Android | На стенде остановить приложение средствами Android, запустить вручную | Новый sessionId, PROCESS_START, uncleanSessions/маркер аварии при наличии; не скрывать разрыв наблюдения |
| Статус, резервуар, батарея | Выполнить чтение и сопоставить с доступными показаниями помпы | PUMP_STATE: lastCommunication, battery, reservoirPumpUnits; неизвестные поля остаются null |
| TBR | На стенде выполнить заранее согласованный тестовый TBR | Решение/ограничение/очередь/передача/результат; HISTORY_RECONCILIATION типа TBR, длительность и ставка |
| Отмена TBR | Отменить установленный стендовый TBR; перечитать статус | Результат отмены и HISTORY_RECONCILIATION TBR_CANCEL с endPumpId |
| SMB | На стенде воспроизвести допустимый вход, при котором обычный алгоритм сам разрешает SMB | APS_INPUT/DECISION/CONSTRAINT/SMB_REQUEST, ровно одна последовательность команды, результат и история |
| Таймаут команды | На стенде прервать ответы после принятия записи транспортом | PUMP_SENT, таймаут/ERROR, PUMP_RESULT с неизвестностью; ни одного автоматического повтора неоднозначного болюса |
| Истечение срока | Задержать очередь до истечения допустимого срока SMB без изменения часов | Отказ устаревшей команды, отсутствие PUMP_SENT для этой команды, нулевая дополнительная подача по истории |
| Неоднозначный ACK | На стенде прервать связь в окне ответа после передачи | Отметка неизвестности; отдельное чтение истории; не трактовать отсутствие ACK как нулевую дозу |
| Отключение сразу после команды | Прервать BLE после принятия передачи | Связанные requestId; последующий статус/история разрешают либо явно сохраняют неопределённость |
| Рестарт во время команды | Только на отдельном стенде завершить процесс в окне команды | Старый sessionId/requestId не запускается повторно; новая сессия читает состояние/историю |
| Повторное чтение истории | Дважды синхронизировать одинаковые записи | Один pumpId/temporaryId, отсутствие второй дозы/дублирующего TBR в БД |
| Расхождение приложения и помпы | Создать контролируемое различие состояния на стенде, выполнить синхронизацию | Предыдущее состояние, новые данные истории, конечные строки БД; различие единиц явно указано |
| Нет повторного болюса | Повторить BG с тем же timestamp и повторить доставку метаданных | LOOP_GATE с отказом дубликату; нет второго SMB_REQUEST/команды/исторической дозы |
| Нет повторного TBR | Повторить вход/историю уже обработанного поколения | Отказ старому поколению/дубликату; отсутствие нового enactment для старого requestId |
| Итоговая доставка | После каждого сценария подачи перечитать историю | reportedDeliveredU либо null; отдельно storedAmountU / reportedDeliveredPumpUnits; неопределённость не скрыта |

## CGM И Планировщик

Выполнить не менее 30 минут для реальных 60-секундного, 120-секундного и штатного 5-минутного источников (или их разрешённого тестового ввода без помпы).
Для каждой строки сверить rawBgTimestamp, bucketBgTimestamp, actualBgTimestamp, referenceTimeUsed, generation, время начала/конца и решение LOOP_GATE.
При расчёте дольше интервала CGM промежуточные запросы могут объединяться; активный расчёт обязан завершаться, затем запускать последнее значение. Это не обещание обработать каждую минуту за минуту на любом телефоне.
Проверить событие углеводов, профиль, временную цель в середине расчёта: старое поколение не публикуется, инвалидируемый диапазон сохраняется, следующий расчёт видит новое состояние.

## Android И Интерфейс

Проверить RU/EN, портрет/альбом, увеличенный шрифт, SMB ON/WAIT/OFF/UNKNOWN, текущую временную цель, возраст BG, данные помпы и dISF-фактор.
После APS/Loop/ответа помпы/изменения цели UI должен обновляться по событию. Секундный возраст не должен запускать запрос к БД каждую секунду.
Проверить экспорт с поворотом экрана и отменой системного выбора файла; повторный экспорт должен оставаться доступным.
Samsung без подключённого SDK/разрешений должен показывать недоступность. Активность не меняет дозирование ни в одном состоянии.

## Критерии Остановки

Любое необъяснённое повторное введение, расхождение дозы, потеря ограничения, скрытая неопределённость или зависшая очередь означает FAIL сценария. Не продолжать испытание подачи до разбора архива.
Наличие пропусков/повреждённых записей не запрещает анализ сохранившихся данных, но запрещает заявлять полноту периода.
Завершённый акт должен содержать таблицу двух моделей, времена сценариев, хеш архива, verdict и ссылки на конкретные eventId; пустые сценарии не считать PASS.
